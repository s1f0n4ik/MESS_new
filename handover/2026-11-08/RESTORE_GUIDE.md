# Восстановление веб-сервиса

Инструкция рассчитана на администратора Linux-сервера, знакомого с Docker, PostgreSQL, DNS и TLS. Перед восстановлением сделайте копию целевого сервера и не выполняйте команды на production без проверки путей.

## 1. Подготовить инфраструктуру

1. Развернуть собственный VPS и установить Docker с Docker Compose.
2. Настроить DNS домена на IP нового сервера.
3. Распаковать `postcards-studio-source-deployed.tgz` в отдельный каталог приложения.
4. Скопировать `.env.example` в `.env` и создать новые уникальные секреты. Перечень требуемых имен находится в `production-env-keys.txt`.
5. Не переносить старые приватные ключи и пароли в открытом виде.

## 2. Восстановить данные

1. Остановить контейнеры приложения, кроме временно запущенного PostgreSQL, если он нужен для импорта.
2. Восстановить содержимое `postcards-studio-data.tgz` в каталог/том, соответствующий `studio-data` в Docker Compose.
3. Восстановить `postcards-studio-collaboration.tgz` в том состояния сервиса совместного редактирования.
4. Импортировать `postcards-studio-db.dump` через `pg_restore` в пустую базу с теми же владельцем и правами, которые заданы в новом `.env`.
5. Установить PDF-шаблон `Postcards_2x2_template_14_blocks.pdf` по пути, указанному в `STUDIO_TEMPLATE_PDF`.

Пример импорта после запуска контейнера PostgreSQL необходимо адаптировать к имени контейнера и значениям нового `.env`:

```bash
docker compose up -d db
docker compose exec -T db pg_restore --clean --if-exists --no-owner --dbname "$POSTGRES_DB" < postcards-studio-db.dump
```

## 3. Запустить и проверить

1. Выполнить `docker compose up --build -d`.
2. Проверить состояние контейнеров и журналы.
3. Проверить HTTPS и `/api/health`.
4. Войти под новой административной учетной записью.
5. Открыть все четыре документа, скачать тестовые PDF и сравнить число страниц, сканы, атрибуции и перенос текста.
6. Выполнить тестовую публикацию, проверить manifest и SHA-256.
7. Настроить новый канал доставки на NAS и проверить его на отдельном тестовом каталоге.
8. Только после успешной проверки переключать выставочные компьютеры на новый сервер.

## 4. Десктопное приложение

1. Использовать установщик `Postcards_2.0.4_x64-setup.exe` с SHA-256 из `VERSION_MANIFEST.md`.
2. Установить одинаковую версию на все четыре компьютера и координатор.
3. Назначить роли PC1–PC4 и проверить подключение к координатору.
4. Сверить открытие четырех локальных PDF без сети.
5. Проверить получение нового тестового релиза, а затем вернуть утвержденный комплект.

## 5. Приемочная фиксация

Записать дату, версии, контрольные суммы, адрес сервера, ответственных лиц и результат тестов. Любое последующее изменение исходников, конфигурации, зависимостей, NAS или сетевой схемы фиксировать отдельной записью.
